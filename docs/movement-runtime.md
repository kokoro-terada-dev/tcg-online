# 共通カード移動：独立モデルでの原子的な確定

## 今回の範囲

独立したMovementStoreに対して、移動・レスト変更・DON付与・公開・並べ替えを一括で確定できるようにします。
既存の通常対戦・一人回し・テスト対戦のMatch、UI、Socket.IOにはまだ接続しません。
CostPlanSessionからの支払い確定、EffectEngine・ResolutionEngine・ReplacementResolverの実行もまだ接続しません。

| ファイル | 役割 |
| --- | --- |
| `movement/types.ts` | 物理カード・領域・付与DON・公開権限・操作・原因・イベントの型 |
| `movement/state.ts` | 状態の整合性、枚数保存、固定枠、世代、付与先の検証 |
| `movement/validation.ts` | コピー前の操作構造検証。未知フィールド、getter、過大配列を拒否 |
| `movement/engine.ts` | 複数操作を隔離したコピーへ適用し、成功時だけStoreを更新 |
| `movement/projection.ts` | プレイヤー別の状態・イベント公開。非公開の識別子も隠す |
| `test/movement.cjs` | 世代・DON・KO・防止・巻き戻し・非公開性・再送・上限のテスト |

## 領域とカード実体

既存DSLの領域に加え、この内部モデルだけにattachedDonを追加します。
既存のZoneRefやカードマスターを変更していないため、Selector/Costから付与DONを選ぶための対応はまだ別途必要です。
付与DONをACTIVE/REST DONとして偽装しません。attachedToに対象のinstanceId/generationを保持します。

カード辞書と領域リストの双方を検証し、カードの重複配置・消失・未配置・古い付与先を拒否します。
キャラクターは5枠、ステージとリーダーは1枠を維持します。firstEmptyは左から空き枠を探します。
ステージ入れ替えは、古いステージの移動と新しい配置を明示した一括操作にします。勝手な上書きはしません。
リーダー移動、所有者の変更、同じ場内のコントロール移動などはこの段階では未対応です。

## 世代と一時状態

[公式総合ルール ver.1.2.1](https://www.onepiece-cardgame.com/pdf/rule_comprehensive.pdf?20260828=) の3-1-6、3-1-6-1、6-5-5-4を確認しています。
場を離れる際の一時状態とDON返却を考慮しますが、以下のgenerationはアプリの参照鮮度を管理する仕組みです。公式ルールのカード同一性の定義と同一ではありません。

- 実際に領域が変わる移動ではgenerationを1増加させ、古い対象参照を失効させる。
- ACTIVE/REST DONは同じコストエリア内の状態区分。レスト変更では世代を変えない。
- 並べ替えだけでも世代は変えない。通常のmoveで同一領域へ移す指定は拒否する。
- キャラクター/ステージが領域を離れると、そのカードに保持したmodifierIds/grantIdsを外す。
- DONが領域を移動した場合も一時状態を外す。印刷された効果はcardIdから別途参照する。
- 場以外で一時状態を持つカードの移動は、解除条件をまだ決められないため停止する。
- キャラクター登場時は通算ターンをenteredTurnへ記録する。場を離れる際は解除する。

modifierIds/grantIdsは将来の効果実体への参照です。実際の継続効果再計算や期限管理を実装したわけではありません。
ライフから手札への移動は、元の裏向き状態を引き継がず手札側の表向き状態へ正規化します。
デッキへの移動は裏向きを要求します。カード詳細・DragOverlayの描画は今回変更していません。

## 付与DON

キャラクターが手札・トラッシュ・デッキ・ライフ・公開エリアなどへ移動する場合、付与DONの返却を同じ確定単位へ含めます。
元の移動が防止された場合はDONを外しません。返却側の判断が未解決・防止となる場合も、不正な付与先を残さず一括処理全体を停止します。
DON返却はRULE_PROCESSINGを原因とし、親の移動イベントへparentEventIdを持たせます。
親が相手効果で移動したからといって、返却の原因まで無条件に同じ相手効果へ分類しません。詳細な原因解釈は今後の因果関係評価器で行います。
付与元カードと返るDONの所有者を実データから判定し、host/guestや画面の上下では決めません。

ACTIVE DONから自分のリーダー/キャラクターへの付与と、付与DONの直接DONデッキ戻しにも内部モデルで対応します。
REST DONを特別に付与する効果やコントロール変更後の特殊な付与は、適用条件が未実装なので推測して許可しません。

## 移動原因とイベント

BATTLE_KO / EFFECT_KO / EFFECT_MOVE / COST_PAYMENT / RULE_PROCESSING / DAMAGE / OTHERを保持します。
KO扱いは、明示的なKO原因でキャラクターエリアからトラッシュへ移動した場合だけです。
手札破棄、コストとしてトラッシュ、バウンス、ステージ入れ替えからKOを発生させません。
DAMAGEを原因にライフから移動する場合は一番上だけを対象とします。ダメージの発生や勝敗を計算する機能ではありません。

内部イベントには前後の物理状態、原因、実行者、効果controller、発動元、resolutionId、親イベントを保持します。
この情報とbefore状態を将来のLast Known Information/Trigger評価に利用します。
イベント配列の直列化順やgroupIdを、そのまま公式の同時効果解決順として使いません。誘発・順序選択はEvent/Resolution層の責務です。

## 移動前のルール判定

呼び出し側がMovementRulesを明示する必要があります。

| status | 動作 |
| --- | --- |
| unresolved | そのまま停止。判定なしで動かさない |
| evaluate | 読み取り専用の提案と仮状態を渡してallow/prevent/deferを要求 |
| certifiedNone | 適用する置換・禁止がないとサーバーが確認済みの場合のみ許可 |

certifiedNoneはテストfixtureでも使いますが、実カードに未対応効果がある状態の回避フラグとして使ってはいけません。
preventされた移動からmoved/KOイベントは作りません。effectモードでは他の独立操作を続けられますが、costモードの防止は一括処理全体を失敗させます。
deferは選択待ち等が必要な状態として一括処理を停止し、まだ結果を確定しません。
この判定口はReplacementResolverそのものではありません。置換後の別操作、複数置換の順序、再適用や選択待ちは未実装です。
判定器は信頼するサーバーコードです。JSONから関数を実行せず、判定中に通信・カード変更・Storeへの再入をしません。

## 一括確定と再送防止

1. 対戦ID、revision、操作・カード・領域の構造を検証する。
2. 現在状態をコピーし、その隔離したコピーに操作を適用する。
3. 付与DON返却などの関連処理も同じコピーで行う。
4. 最後に全カードの整合性を再検証する。
5. 成功時だけStoreを新状態へ差し替え、revisionとトランザクションID台帳を更新する。

途中で移動先が埋まっている、不正参照、判定待ち、コスト防止などが起きた場合は元の状態・台帳を一切変更しません。
同じトランザクションの再確定、古いrevision、判定器からの再入を拒否します。
コストモードでは同一実体の重複に加え、親カード移動に伴い暗黙に返却されるDONとの重複も、最初の状態で検証します。
順序依存コストを解決した実装ではなく、前段の独立支払い契約を維持します。

このStoreは独立モデル内の確定だけを保証します。既存Matchの盤面とProgression/gateを別々に更新してつなぐことは禁止です。
実対戦への接続時は、移動・支払い結果・解決位置・gate・要求完了を一つの親トランザクションで差し替える必要があります。
複数Storeを同じ対戦の「現状態」として並立させないでください。

## 公開Viewと履歴

snapshot()と内部イベントはサーバー専用です。MovementStore自体はJSON.stringifyを拒否します。
クライアントへ送るのはprojectMovementState/projectMovementEventsの結果だけとします。

- 相手の手札・裏向きライフ・山札はcardIdだけでなく実体ID・世代も隠す。
- 自分の手札と表向きの領域は確認可能。DONデッキは公開領域として扱う。
- 一時公開はscopeIdとviewerを限定する。終了・移動・conceal付きの並べ替えで権限を外す。
- concealは一時公開権限を閉じる指定であり、表向きライフなどを勝手に裏返す操作ではない。
- 非公開領域へ戻すカード群は、相手向け履歴でIDや出発領域の順番を出さず、移動先別の件数へ集約する。
- その場合の公開イベントは安全な内容で並べ直し、付随する公開DONの返却順から非公開順序を推測させない。
- ACTIVE/REST/付与DONの表示リストも公開用に正規順へ並べる。コストエリアの表示順を、非公開の親移動順の代用にしない。
- 生のイベント番号、parentEventId、modifierIds、発動元の非公開参照などを公開ログへ流さない。

公開履歴の配列順は解決順ではありません。ルール処理には常に内部の構造化イベントを使います。
公開権限や現情報の正確性は、サーバーのルール処理器で確認してから操作へ渡す必要があります。

## 安全上限

カード256枚、一次操作64個、イベント512個、完了トランザクションID4,096個を暫定上限とします。
上限はアプリの安全措置であり、ゲームルール上の枚数やターン制限ではありません。
台帳の古いIDを黙って忘れて再実行を許すのではなく、上限到達時は明示的に停止します。永続化と長期台帳は今後検討します。
世代の数値上限でも折り返さず停止します。未知フィールド、getter/setter、疎配列、過大な操作配列はコピー前に拒否します。
