# 隔離v3：未生成カードだけの差分生成

基準 `94aff70`。前回の集計から状態が完全生成の1,157番号を除外し、残り1,728番号だけを処理した。旧個別JSONの読み込み・再生成・全件検証はなし。承認カタログは目録のIDのみ読み、承認済みの定義にはアクセスしない。

## 実装

- `PLAY_BY_EFFECT(from: "deck")`：現在の解決内で自分が閲覧した1枚だけを登場させる。満枠処理・登場誘発・個体世代の検証は既存経路を使う。
- `MOVE_CARD.excludeCards`：閲覧した集合から選択済みの個体・世代を差し引き、自分のトラッシュへ送る。残札を選び直す操作は不要。
- `SHUFFLE_DECK`：サーバー側で自分の山札をランダムに並べ替え、閲覧権限を閉じる。シャッフル後に古い閲覧権限で登場できない。
- `CALL_EFFECT_BODY`：同じカードの登場時・KO時・カウンター本文のうち、発動元の領域や発動コストに依存しないものをライフトリガーから解決。実際に登場・KOさせたり、イベントの印刷コストを再度払ったりしない。[公式総合ルール](https://www.onepiece-cardgame.com/pdf/rule_comprehensive.pdf?20250912=)
- カウンターの追加手札支払いとイベントMAINの追加支払い・モード選択は既存の選択、任意支払い、成功分岐を再利用。カウンターの支払い辞退では後続効果を解決しない。[公式カード別Q&A](https://en.onepiece-cardgame.com/pdf/qa_op02.pdf?20240405=)
- 継続効果は非循環の公開メタデータ・DON!!条件を追加。生成器は名前指定、複合ガード、検索後の処理、順序付きドロー、注記の結び付けも拡張した。

新規契約は `3.0.0-subset.51` / `v3-subset-compiler.51.1`。既存Schemaファイル・承認記録・通常対戦・一人回しは変更なし。

## 残件・再開

残る不足の根拠あり38番号（重複あり）。KO時のDON!!支払い10、相手DON!!操作6、相異なる複数対象5、相手によるモード選択5、バトル終了誘発3など。今回は多枚数の満枠登場、相手の手札を戻してシャッフル、戻した枚数依存のドロー、発動元の領域・追加コストに依存する本文呼び出しを対応済みとしていない。ターン条件を解決時の単なるIFに置き換え、発生時の誘発可否を変えてしまう変換も除いた。

要裁定・データ・既知の検証不一致などの保留231番号、原因未分類1,352番号。集計分類は重複し、未分類は機能不足を意味しない。終了条件B。参照先の処理・発動条件・印刷情報を確定できないものは保留し、全件対応の完了とはしない。根拠のある既知の機能不足も残る。

未承認JSONはGit管理外の `local-data/v3-draft-delta-ready/definitions`、残件の原文位置・分類根拠は同名の `-reasons` ディレクトリ。再開時は `tools/generate-v3-draft-delta.js <catalog> <source.csv> <ledger.json> <baseline.json> <new-output-dir>` に今回の `remaining-input.json` を渡すと、今回分も含む完全生成を除外する。Schemaを更新する場合は対象CompilerをTypeScriptで出力し、`node tools/build-v3-deck-play-profile.cjs` で生成する。
