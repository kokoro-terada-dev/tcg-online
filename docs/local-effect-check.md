# ローカル専用：効果画面を2ウィンドウで確認する

これは実カードの能力や正式な自動対戦ではありません。
固定のテスト動作「手番側が手札を1枚捨て、1枚引く」を既存のルームと画面で確認します。
起動時のフェーズ進行はフィクスチャです。実対戦の初期処理として使用しないでください。
固定テスト効果のDSLには実カードマスターを渡しません。保存デッキとマスターのカード種類に
食い違いがあっても、このテストに限って初期化を妨げないようにしています。
画像・カードID・デッキ内の種類は保存デッキを使用します。
基本バトルのパワーだけは、サーバー起動時に読み込んだマスターを対戦ごとに別途固定して参照します。
実カードの個別能力や、カードの使用条件全般を検証するものではありません。
通常のテストサーバーのマスター読込や、正式な効果エンジンの種類整合性検証は変更しません。

## 起動手順

1. VS Codeで `C:\Users\kensh\workspace_server` を開きます。
2. メニュー「ターミナル」から新しいターミナルを開きます。
3. 次を実行します。

```powershell
cd C:\Users\kensh\workspace_server
npm run dev:effects
```

4. サーバーのビルドが終わり、`LOCAL FIXTURE ONLY` とViteの `Local:` が表示されるまで待ちます。
5. `Local:` に表示されたURLをブラウザーで開きます。通常は `http://127.0.0.1:5189/` です。
   使用中のポートがある場合は別番号になるため、表示されたURLを使用してください。
6. 同じURLを別ウィンドウでも開きます。外部公開サイトのURLではありません。

## デッキと画像の準備

- 各ウィンドウでトップ画面から必要な画像ZIPを読み込みます。画像の読込状態はウィンドウ別です。
- このローカルURL上で使用できる保存済みデッキを用意します。
- 公開サイトや別ポートで保存したデッキは、ブラウザーの保存先が異なるため自動では出ません。
  必要なら従来のデッキ登録/読込操作で用意してください。
- 一方でデッキを追加した後、もう一方に反映されない場合は、対戦前に再読み込みします。

## 確認手順

1. 両ウィンドウでトップから「テスト対戦」へ進みます。
2. 一方で「ルーム作成」、もう一方で4桁コードを入力して「入室」します。
3. 両者ともデッキを選び終えてから、両者でREADYを押します。
4. ホストが「対戦開始」を押します。従来の盤面配置と「待機中」のパネルが表示され、先攻のホストにACTIVE DONが1枚追加されます。初回はドローせず、手札は5枚です。この時点では効果は開始しません。
5. ホストが「盤面を見る」→自分のリーダーをタップ→登録済み効果の「発動する」を押します。
6. 手札から支払い用の1枚を選び、「選択を確定」を押します。
7. 「実行」でそのカードがトラッシュへ移動します。
8. 「処理を進める」で1枚ドローし、両者の画面が「待機中」に戻ります。
9. 相手側では手札内容が裏向きのまま、枚数と公開トラッシュだけ更新されることを確認します。

「盤面を見る」で効果パネルをたたみ、自分のリーダーをタップすると、
固定テスト用の登録済み効果一覧を参照できます。ホスト側では「発動する」で
手札のコスト選択へ進めます。実カード本来の能力の一覧ではありません。
アタック可能なタイミングでは先にカード操作メニューが開くため、「登録済み効果」を押して一覧へ進みます。

コード更新後は起動済みのターミナルでCtrl+Cを押し、`npm run dev:effects`を再実行してください。
両ブラウザーも再読込し、ルーム作成・入室からやり直します。
この起動方法ではバックエンドはソース変更だけでは自動再起動しません。

支払い前は「キャンセル」でカードを動かさずに「待機中」へ戻せます。応答が不明なら「再同期」を押します。
処理完了後は、ホストのリーダーの一覧から同じ固定テスト効果を再度発動できます。
初期盤面からやり直すときは「ルームへ戻る」から再度READY/開始します。
通常の自由移動は、このテスト効果モードでは使用できません。

## 手札からのテスト登場

1. 自分の手番で、効果処理が終わり「待機中」になっていることを確認します。
2. 自分の手札のキャラクターまたはステージをタップします。
3. 中央のカード操作ダイアログで「テスト登場」を押します。
4. キャラクターは左から最初の空き枠、ステージは空きステージ枠へ、表向き・アクティブで移動します。

枠が埋まっている場合は「空き枠なし」と表示し、登場ボタンを無効にします。
既存のカードは上書きせず、手札も減りません。相手の画面では登場したカードだけ公開され、残った手札は非公開です。
「詳細」で従来どおり大きなカード画像を確認できます。

カード種類は保存デッキのcardTypesを使用します。イベント等はこの登場操作の対象外です。
これは盤面移動と同期を確認するためのローカル限定・コストなしのテスト操作です。
DON支払い、色条件、場のカードの入れ替え、登場時効果の自動発動はまだ行いません。
相手のカード・相手の手番・効果処理中・対戦終了後の登場はサーバー側でも拒否します。
盤面状態が更新されると古いカード操作ダイアログは閉じます。

## テストアタック

1. 「テスト手番交代」でホスト→ゲスト→ホストと進め、通算3ターン目にします。
2. ホストの「盤面を見る」から、自分のアクティブのリーダーをタップします。
3. 中央メニューの「テストアタック」を押し、相手リーダーをタップします。
4. 確認ダイアログの「はい」で攻撃元がレストし、攻撃元→対象の矢印を表示します。
5. ゲスト側の「ブロックしない」でカウンター判断待ちへ進みます。
6. ゲスト側の「カウンター終了」でダメージ判定待ちへ進みます。
7. パワー情報が揃っていれば、防御側の「テストダメージ判定」で基本バトルを解決できます。

各自の最初のターンは攻撃できません。攻撃元は自分のアクティブのリーダー・キャラで、
キャラは登場したターンには攻撃できません。攻撃先は相手リーダー、またはレスト中の相手キャラです。
選択・確認中のキャンセルは未確定の画面選択を閉じるだけで、カードはまだレストしません。

判定用パワーはマスターのpowerと攻撃元の付与DONを使用します。防御側の付与DONは加算しません。
攻撃側が防御側以上なら、キャラはトラッシュへ移動します。リーダーへのダメージでは、防御側だけにライフ一番上の確認ダイアログを表示します。
画像をタップすると詳細を確認でき、「戻る」で選択へ戻れます。「手札へ」は自分の手札へ、「トリガー発動」は表向きで公開エリアへ移動します。
確認中、攻撃側には「相手のライフ確認待ち」と表示し、裏向きのライフ内容は送信しません。
ライフ最後の1枚を受け取っただけでは敗北せず、ライフ0枚で次のダメージを受けると敗北します。
攻撃側が下ならカードを移動せずにバトルを終えます。終了後は通常の待機中メインに戻ります。

今回はトリガーの宣言と公開エリアへの移動までの基本テストです。カード固有のトリガー効果やトリガー所持の判定は行いません。
「トリガー発動」は全カードで選択可能なため、実際に使用できるかはカード内容を確認してください。
確認中は手番交代・登場・他の効果開始を止めます。応答を確認できない場合はダイアログ内の「再同期」を押してください。
ブロッカー能力に基づく合法性判定や手札カウンター、アタック時/KO時効果、ダブルアタック等の個別能力は未接続です。
正式なカード効果を含む自動対戦全体にはまだ対応していません。

### テストブロック

1. 防御側のキャラクターエリアにアクティブのキャラを用意します。テスト登場したキャラでも選択できます。
2. 相手のアタックが確定し「ブロック判断待ち」になったら、防御側のパネルで「テストブロック」を押します。
3. 表示された候補から1枚を選び、「選択を確定」を押します。「閉じる」は候補選択だけを閉じます。
4. 選択したキャラがレストし、元の攻撃元からそのキャラへの矢印に変わり、カウンター判断へ進みます。
5. カウンター終了後のダメージ判定も、そのキャラを対象とします。元の対象のライフは減りません。

これはローカル限定の進行確認用です。マスターにブロッカー能力情報がないため、現在は能力の有無に関係なく自分のアクティブキャラを候補にします。
実カードのブロック可否やブロック禁止能力は判定しません。レスト中・相手側・キャラ以外・古い参照・判断終了後の選択はサーバーでも拒否します。
候補がなければボタンは表示しません。「ブロックしない」は従来どおり使用できます。
カウンター用DSLの処理中は矢印を保持し、判断終了操作は効果完了まで拒否します。

マスターなし、IDなし、powerが空欄/null、種類の明確な不一致、未対応の修正値などは0と扱いません。
パネルに「?」「パワー情報不足・未対応」と表示し、ダメージ判定ボタンを表示しません。
既定のマスターはworkspace_server/public/card-master.jsonです（TEST_CARD_MASTER_PATH指定時はそのファイル）。
CSVから作り直す場合は従来のnpm run build:card-masterを使い、npm run dev:effectsを再起動します。
起動後や対戦中にファイルを書き換えても、その対戦のパワーは差し替わりません。

## 両プレイヤーの操作を確認する

1. 待機中に、手番側のパネルに表示される「テスト手番交代」を押します。
2. 両画面のターン番号が増え、操作できる側が入れ替わることを確認します。新しい手番側は1枚ドローし、DONが最大2枚追加されます。
3. ゲスト側で「盤面を見る」→自分のリーダー→「発動する」と進みます。
4. 手札の選択・「実行」・「処理を進める」を確認します。
5. 待機へ戻った後、ゲスト側の「テスト手番交代」でホストへ戻せます。

リーダーが異なるデッキでも、両者のリーダーへ同じ内容の固定テスト効果を登録します。
同じリーダーIDには重複登録しません。IDの対応付けは実カードの能力を表すものではありません。
効果中やコスト選択中は手番交代ボタンを表示せず、サーバー側でも拒否します。

これは正式なターン終了処理全体ではなく、基本処理と権限・タイミング・同期を確認するローカル専用操作です。
新しい手番側の付与DONをACTIVE DONへ戻し、リーダー・キャラ・ステージ・REST DONをアクティブにした後、
1枚ドローし、DONデッキから最大2枚をACTIVE DONへ追加します。DONが足りない場合は残り枚数だけ追加します。
期限付き効果の解除、ターン開始/終了時のカード効果は未実装です。
未知の付与効果などを検出した場合は交代を拒否し、手番や盤面を途中まで更新しません。
本番起動では有効化できず、公開の通常対戦や一人回しには追加していません。

基本のターン開始手順は[公式ルールマニュアル](https://onepiece-cardgame.com/pdf/rule_manual.pdf?20251201=)のゲームの流れを参照しています。
今回の追加はビルドと限定した自動確認のみで、端末上での操作確認は実施していません。

## 山札切れによる終了

通常ドローまたは固定テスト効果で山札が0枚になった場合、サーバーで敗北を確定します。
最後の1枚を通常ドローした場合、そのカードを手札へ移動して終了し、DON追加は行いません。
すでに山札が0枚なら、追加のドローやリフレッシュをせず終了します。
両者が同時に山札0枚になった場合は、勝者なし・両者敗北として保持します。

両画面に各自のWIN／LOSEを約3秒表示し、その後も効果パネルに終了結果を残します。
対戦終了後は新しい効果や手番交代を拒否します。再同期やカードの詳細確認は可能です。
ルームは自動解散せず、「ルームへ戻る」で従来どおり戻れます。
山札切れに加え、基本バトルでライフ0のリーダーがダメージを受けた場合も同じ結果表示を使用します。

## 終了と安全境界

- 起動したターミナルでCtrl+Cを押すと、検証用フロントとバックエンドを終了します。
- ブラウザーを閉じるだけでは起動用プロセスは終了しません。
- バックエンドは空きポートを選び、127.0.0.1だけで待ち受けます。
- PC内の2ウィンドウ用です。iPhoneなど別端末からの接続やLAN公開は対象外です。
- NODE_ENV=productionでは起動を拒否します。
- VITE_TEST_SERVER_URLは起動したVite子プロセスにだけ渡します。.envやVercel/Render設定を変更しません。
- 通常のnpm run dev、公開サーバーの起動コード、実カードのマスター/効果登録は変更しません。

## 検証済み範囲

実Socketで入室から固定効果完了までを自動テストしています。
実ブラウザー2画面でも、入室/デッキ/READY/開始/未払いキャンセル/選択/支払い/ドローと
相手の手札非公開を確認しました。ブラウザー検証用の架空画像・HTML・スクリプト・結果画像は
local-data内のGit対象外ファイルです。実カード画像や利用者の保存データを変更していません。
