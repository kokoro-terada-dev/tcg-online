# PR21: カード効果DSL案の構造解析

## 解析方針

PR20の未解釈3,620箇所を2,693グループにまとめ、影響カード番号数と出現数で優先順位を付けた。集計用の正規化は生成には使わず、元の日本語から条件・対象・数量・選択者・操作・順序を分離する。PR19/20の完全一致処理を先に適用する。複数操作のうち一部でも不明なら、その行のDSLを出さず、原文と未解釈箇所のUTF-16オフセット・理由を残す。未解釈の行や版差が残るカードに完全な定義は出さない。

上位では、トリガーのドロー後手札破棄22番号、登場時の同型14番号、トリガーの自分のリーダーまたはキャラへのターン中強化13番号を既存DSLで表現できた。一方、自身のライフからの登場56番号、任意枚数のアクティブDON追加17番号、所有者を明示しない手札戻し13番号、単独のキーワード注釈は、安全に表現できると断定せず保留。メイン効果を呼び出す文は53番号のうち新たに本文を確定できた1番号だけ変換した。

複合パターンは優先順位で1分類に数え、同じ番号が複数行を持つ場合はパターン間で重複する。解決中の枚数条件は `IF`、対象条件は現在値の `SELECT`、2領域で合計最大1枚は `CHOOSE_MODE` と各領域の0～1枚選択を使用。自分の手札破棄は後続の `IF` でその時点の手札を数え、指定数に足りなければ可能な枚数を選ぶ。ターン中の補正は解決時のターンプレイヤーを確認してそのターン終了で失効。支払い、不明な所有者、2領域をまたぐ合計2枚以上、曖昧な効果順序は変換しない。[公式総合ルール §1-3-2、§4-8、§4-10、§8-3-3、§8-4-4](https://en.onepiece-cardgame.com/pdf/rule_comprehensive.pdf)

### 公式CSVの原文とDSL案の照合例

- EB05-042: 登場時の「2枚引き、手札2枚を捨てる」は `DRAW(2)` → 現在の自分の手札枚数に応じた非公開の厳密枚数選択 → トラッシュ移動。
- EB01-022: 自分のターン終了時、手札2枚以下の場合のみ2枚引く。 `TURN_END(SELF)` → `IF(SELF.handCount <= 2)` → `DRAW(2)`。
- OP01-058: カウンターで自分のリーダーまたはキャラを最大1枚強化し、その後、相手の現在コスト4以下を最大1枚レスト。対象束縛は別で、後段を前段の選択成功に依存させない。ライフトリガーの別本文も保持した。
- OP05-020: ライフトリガーの自分のリーダーまたはキャラ1枚までを+1000。持続はトリガーを発動した側のターン終了固定ではなく、現在のターン終了。
- OP05-036: ブロック時、相手の現在コスト4以下のキャラを最大1枚レスト。既存 `ON_BLOCK` から `SELECT` と `REST`。
