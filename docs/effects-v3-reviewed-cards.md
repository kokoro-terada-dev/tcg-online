## ファイルの役割

- `server/data/effects-v3-reviewed/sources/`: 確認時点の基本情報と能力を保存する原資料スナップショット。追加登録では既存の履歴を上書きせず、新しいスナップショットを追加します。
- `cards/`: 実際の命令JSON。カード専用TypeScript分岐は使っていません。
- `manifest.json`: サーバー配置物として信頼する承認表。定義・原文・Compiler・Registry・ルール版のハッシュを固定します。
- `server/src/test/effects/v3/reviewedCatalog.ts`: 上記の一致確認。新しい承認を自動生成しません。
- `reviewedDeck.ts`: 未承認IDや不正な枚数等を拒否する入口。大会の禁止・制限やブロック構築ルールまでは検証しません。

原資料のハッシュは、JSON.parseした値をJSON.stringifyしてSHA-256を計算します。
改行差は無視しますが、文字・数値・配列順やキー順の変更は承認の再確認が必要です。

## 追加登録の条件

1. 公式カード情報の数値・特徴・本文・トリガーを確認します。CSVの推定だけでは承認しません。
2. すべての能力を既存Registryの命令で正確に表せるか確認します。未対応の能力だけを削除して登録しません。
3. 必要な公式Q&A・裁定を確認します。未確認ならneeds_review/unsupportedとして実行経路へ入れません。
4. JSON定義と原資料を保存し、実装の確認後にだけ独立した承認表を更新します。
5. Compiler/Registryを変更した場合、旧ハッシュを新しいものへ一括で自動承認し直しません。

現時点で未登録のST02カードは、継続的なDON条件、特徴付きサーチ、登場トリガー、DONのアクティブ化等の未対応部分があります。
## 開始手順の基盤

`ReviewedV3Setup`は、サーバーが読み込んだ承認済みカタログと、検証済みの2デッキだけを受け付けます。

1. サーバーの暗号学的乱数で、先後を選ぶ権利を一方へ渡します。この時点では手札は配りません。
2. 選択権を持つ側が先攻/後攻を選ぶと、両者へ5枚ずつ配ります。相手の手札は非公開です。
3. 先攻側から順に一度だけマリガンを選びます。引き直す場合は5枚すべてを戻してシャッフルし、5枚引きます。
4. 両者が確定したら、元のデッキ一番上がライフ一番下になる順に、リーダーのライフ値の枚数を裏向きで置きます。
5. 先攻の1ドンだけを追加し、追加ドローをせず1ターン目のメインを開始します。

根拠は総合ルール5-2-1と初回ドロー/DONフェイズです。開始時能力を持つリーダーは今回のプリセットには含みません。
選択権のない側、順番前/二度目のマリガン、古いrevision、再送内容の書き換えを拒否します。同一要求の再送は二重に配りません。
内部のクラス名`V3SyntheticMatchCoordinator`は互換性のため維持していますが、実カードは`reviewedLimited`モードと、サーバー読込済みカタログのブランドで区別します。
実カードモードでは、発動条件とコストを事前確認し、支払えない発動で解決待ちに入らないようにしています。

## ローカルで試す手順

1. `npm run dev:effects-v3`でv3検証サーバーを起動します。通常サーバーとは別のローカル専用プロセスです。
2. 表示されたURLを2つのブラウザーで開き、画像ZIPを読み込んでv3検証画面へ進みます。
3. 一方でルームを作成し、もう一方は4桁コードで入室します。
4. ホストが「限定実カード」を選び、両側で「限定検証・緑キッド」を選択してREADYにします。モード変更時は両者の選択とREADYを解除します。
5. ホストが「限定実カード対戦を開始」を押します。サーバーが抽選し、選択権を持つ側だけが先攻/後攻を選びます。
6. 先攻から順に手札を確定します。相手の手札は非公開で、両者の確定まで盤面操作はできません。
7. 盤面では登場・リーダー効果・アタック・ブロック・手札カウンター・ダメージ確認を使用できます。登場時の対象選択等は中央の処理パネルで進めます。
8. ライフ0でリーダーにダメージが通ると両者へWIN/LOSEを表示します。ホストの「ルームへ戻る」で同じコードのルームへ戻ります。

このモードのデッキはサーバー指定プリセットだけです。ローカルの任意デッキを実カード承認済みとして使用できるわけではありません。
合成検証の単発/連続操作は「合成検証」に残しています。通常対戦・一人回しには接続していません。

### 確認範囲

- ローカルSocket.IOの2クライアントで、ホスト先攻/ゲスト先攻の2ケースについて、準備→抽選→マリガン→実カードのリーダー攻撃とDON付与→非公開ライフ取得→勝敗同期→同じルームへの復帰を確認しました。
- 攻撃される側はカウンターを使用せず受ける選択です。すべての手札・カード効果の組合せを総当たりしたテストではありません。
- 別途、既存の合成ケース1件、画面の選択権と古い状態の拒否2件、両ビルドを確認しています。
- 実機iPhoneの表示・実機間ネットワークは未確認です。サーバーは従来通りloopback/ローカルOrigin限定で、本番公開・DB保存・再接続復旧は未対応です。
